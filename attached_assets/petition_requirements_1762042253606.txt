Build a public petition system for demanding the resignation of specific law-enforcement officers. It must support unlimited petitions and signatures, optimized for Facebook sharing and plain-text compilation for mailing or emailing.

The public petition page must display editable fields for Officer Name, Department, Location (City/County/State), Offense Description, and a Bottom Link that redirects to any website of the admin’s choice. Signers must enter a Full Name (required) and a Typed Signature (required), with an optional Drawn Signature using mouse, touchpad, or mobile device. A checkbox must confirm: “I affirm this is my name and signature for this petition.”

Upon submission, the system stores the Full Name, Typed Signature, Drawn Signature (if provided), UTC timestamp, and Submitter Name (the person who created the petition—visible only to the admin). A live counter must display total signatures. After signing, users see “Thank you for signing. Your signature has been recorded,” followed by a button labeled “End law-force corruption: share on Facebook,” which opens the Facebook share dialog with proper title, description, and image. The submitter’s name must never appear publicly.

Facebook sharing must use Open Graph metadata including the petition title, a short description with the officer’s name and department, and a neutral image. No UTM or referrer data should be captured. The Admin Panel is accessible only to the admin, from inside the app, specifically from the welcome page, and must not be publicly linked.

Inside the Admin Panel, a Petition List must show all petitions shared on Facebook in sequential order, displaying each petition’s submitter name (admin-only) and opening its own management screen. The Manage & Edit feature allows the admin to view petition details and signatures and to edit all petition content, including Officer Name, Department, Location, Offense Description, an “Add To” section for adding or removing text, and the External Bottom Link. The Compile Petition feature must generate a page-numbered plain-text file containing the petition title, officer, department, location, offense description, any additional text, date range of included signatures, total count, and a full signature roster with typed signature, full name, and UTC timestamp, inserting a page marker after every sixty lines and naming files in the format petition_[officer_lastname]_[YYYYMMDD_HHMM]_plain.txt. The Export ZIP option allows the admin to email a ZIP containing the compiled petition and a short readme (petition title, compile date, and signature total) to any email address they choose. Analytics inside the Admin Panel must show total signatures, signatures today, and last compile time.

No emails are collected from signers. There are no anti-spam, moderation, verification, or deletion features, and no privacy or terms pages. No IP, user-agent, or referrer tracking, no CSV or PDF exports, and no external authentication beyond the in-app admin access. The interface must be mobile-friendly, support touch input for signatures, and perform smoothly with unlimited petitions and signatures while validating required fields clearly.

The Offense Description field must include the description of the events as provided by the individual who purchased and created the petition, together with an AI-redrafted version of those same facts for clarity and readability. The redraft should preserve the factual content while improving structure and flow. Figurative comparisons, such as likening “kittens and rainbows” to “Charles Manson and hell,” may be included to illustrate the severity of the officer’s actions toward the citizen, and the wording provided by the admin or purchaser must be preserved exactly as entered. The Bottom Link of each petition must remain editable by the admin and visible on the page footer.

A unique, shareable petition page link must be automatically generated each time a user purchases a petition. The system must create and maintain within the Admin Panel a Petitions Folder storing all petition links in descending order, newest first. Each link must instantiate a petition inheriting all functions and specifications listed, including dynamic fields, signature requirements, consent checkbox, live counter, Facebook integration, success-screen share button, admin-only submitter visibility, Manage & Edit features, “Add To” and bottom link, plain-text compilation, ZIP email option, and analytics. Each entry in the Petitions Folder must show its creation timestamp and provide actions to open, copy URL, compile, email ZIP, and edit the petition. Upon purchase of a petition, a copy of the link created by that purchase must be automatically provided to the buyer within their confirmation email.
